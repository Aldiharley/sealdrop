MINOR 4 (case folding)
- extract.rs:291 now folds with `prefix.to_uppercase().to_lowercase()`. The doc comment is at extract.rs:276-283.
- New cases in `case_collision_detector`: ας/ασ, ς/Σ and ϐ/β collide.
- Wording updated in spec §9 (spec:876-881), README Security item 7 (README.md:358) and Appendix C row e (spec:1082).
- DEVIATION from the brief: the brief asked the docs to say that collisions outside simple folding "are caught by the hash check". That is not true of this code:
  - extract writes with `File::create`, which truncates.
  - Each file is hashed as it is written and compared only with its own entry.
  - So a later file that NTFS/APFS folds onto an earlier one silently replaces it, and every hash still matches.
- The docs therefore say these collisions are NOT refused up front, and the hash check does not catch them either (the later file replaces the earlier one). Making the brief's claim true would need `create_new` in extract, which would also change Appendix C row d (duplicate entries). I left the code alone and flagged it.
