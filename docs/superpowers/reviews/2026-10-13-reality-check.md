## Discrepancies vs VALIDATION.md

1. Header says run at commit `6913101`; HEAD is `bce77ea` (docs-only commit on top; test results do not differ).
2. CCTV: doc says the run "did not print the reason" for the 19 skips. It does: "identity type not supported by age 0.12.1". All 19 are hybrid vectors, which backs the doc's attribution.
3. Doc's manual session used port 8787 and a 2-minute window; I used 8788 and 1 minute as instructed. Not a product discrepancy.
4. `sealdrop recipient | head -1` did not panic for me in 31 tries. The panic reproduces with `| true` (exit 101) and occasionally with `read`. It depends on whether the reader closes before the second line is written. The doc presents it as a consistent result of `head -1`.
5. Expiry check: my server died between tool calls, so the reopen needed a restart, and the "expired" result was obtained after restart on the persisted DB. This shows persistence works, but I did not observe an uninterrupted server across the window.
6. The working tree has untracked, uncommitted files `docs/design/assets/{README.md,banner.png,icon.png}` (plus an older tracked `icon-placeholder.png`). Not created by this check and not mentioned in VALIDATION.md.
7. Not validated by anyone, by the doc's own admission and by me: installers installed/launched, the real packaged desktop UI (screenshots are mock-mode browser renders), the interactive passphrase prompt.
8. `receipt fetch` needs `SEALDROP_RELEASE_TOKEN`; after the window it errors with "set SEALDROP_RELEASE_TOKEN..." when unset. Not a doc claim, noted only.

## Verdict: NEEDS WORK (for production certification); the validation document's claims are PRODUCTION-EVIDENCE OK as stated

Every numeric and behavioural claim in VALIDATION.md reproduced independently: the toolchain gates, 129/129 tests with identical per-binary counts, CCTV 128/19/0, 3 interop passes with no skip, a clean desktop build, the timed-release lifecycle (exit 0, "unlock count: 1", stock age refusal, plain-package interop, exit 2 "expired"), tamper rejection with no output, and the screenshot and bundle artefacts. The document is accurate about its evidence.

I still default to NEEDS WORK for "production ready", for reasons the doc itself admits plus my findings. The `sealdrop recipient` closed-pipe panic (exit 101) is a real, unfixed defect in a command whose output is meant to be piped. The packaged desktop app and the installers have never been launched or tested, and the screenshots come from mock data. The interactive passphrase prompt is untested. The 19 hybrid (age1pq) vectors are skipped because the age under test lacks support, so post-quantum interop is unproven. The expiry path was exercised only on one machine, with a 1-minute window. Fix the panic (handle `BrokenPipe`/use `writeln!` with error handling), smoke-test the installed desktop app, and this should be a clean pass.
